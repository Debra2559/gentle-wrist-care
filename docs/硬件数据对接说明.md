# 腕安 · 硬件数据上报对接说明（给硬件/固件同学）

## 1. 概述

护腕通过 HTTP 把监测数据实时推送到云端数据库。你只需向一个 HTTPS 接口 POST JSON，服务端校验数据格式后写入数据库，App 端会自动展示最新数据与预警。

## 2. 接口地址

| 环境 | URL |
| --- | --- |
| 联调（预览） | `https://project--eb0b59ab-496e-4411-8bae-ad853b9d5211-dev.lovable.app/api/public/ingest` |
| 正式（发布后） | `https://gentle-wrist-care.lovable.app/api/public/ingest` |

- 方法：`POST`
- 推荐上报节奏：固件本地缓冲，每 5~10 秒批量上报一次（一批最多 200 条）；弱网时可缓存重发。

## 3. 请求头

```
content-type: application/json
```

当前接口无需鉴权令牌，直接 POST 即可。

## 4. 请求体格式

```json
{
  "samples": [
    {
      "device_id": "WRIST-001",
      "session_id": "S001",
      "timestamp_ms": 1724980000000,
      "theta_fe": 12.3,
      "theta_rud": -4.1,
      "pressure_kpa": 3.2,
      "temperature_c": 33.5,
      "battery_pct": 86,
      "quality": 0.97
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 含义 | 取值范围 |
| --- | --- | --- | --- | --- |
| device_id | string | 是 | 设备唯一编号 | ≤64 字符 |
| session_id | string | 是 | 本次监测会话编号 | ≤64 字符 |
| timestamp_ms | int | 是 | 采样时间戳（毫秒，Unix epoch） | ≥0 |
| theta_fe | number | 否 | 腕部屈伸角（度） | -180 ~ 180 |
| theta_rud | number | 否 | 腕部桡尺偏角（度） | -180 ~ 180 |
| pressure_kpa | number | 否 | 佩戴压力 | 0 ~ 100 |
| temperature_c | number | 否 | 腕部温度（℃） | -20 ~ 80 |
| battery_pct | int | 否 | 电量百分比 | 0 ~ 100 |
| quality | number | 否 | 信号质量 | 0 ~ 1 |

- 除三个必填字段外，其余字段按设备当次实际测到的通道上送即可，缺测的通道直接省略该字段。
- 同一批 samples 可混不同 device/session，但建议按会话分组。

## 5. 响应

| HTTP 状态 | 含义 |
| --- | --- |
| 201 `{"ok":true,"stored":N}` | 成功写入 N 条 |
| 400 `invalid_json` | 请求体不是合法 JSON |
| 422 `invalid_payload` | 字段校验失败（响应里带前 5 条具体原因） |
| 500 `store_failed` | 服务端写入失败，请稍后重试 |

非 201 均应重试（建议指数退避），422 除外——先修正数据格式。

## 6. 联调用 curl 示例

```bash
curl -X POST "https://project--eb0b59ab-496e-4411-8bae-ad853b9d5211-dev.lovable.app/api/public/ingest" \
  -H "content-type: application/json" \
  -d '{"samples":[{"device_id":"WRIST-001","session_id":"S001","timestamp_ms":1724980000000,"theta_fe":12.3,"pressure_kpa":3.2,"battery_pct":86}]}'
```

## 7. 注意事项

1. 时间戳请用设备实测的 Unix 毫秒时间，服务端会按 (session_id, timestamp_ms) 建索引，App 按时间轴展示。
2. 每次断网重连后尽量补发缓存数据；数据库按行追加存储，重复上报同一时间点不会产生覆盖问题，但建议固件侧去重。
3. 如需新增通道（如拇指角、辅助力矩），只需加字段，通知产品方同步加列即可，协议不变。
4. 请全程使用 HTTPS 上报。
