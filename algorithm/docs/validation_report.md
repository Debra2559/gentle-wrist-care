## 当前结论

当前代码、接口、Mock 数据和测试已对齐以下现场协议：

- 前臂背侧 `forearm` IMU 与第 3 掌骨手背 `hand` IMU。
- 独立 CAL 文件；必需中立、掌屈、背伸和尺偏，桡偏可选。
- 任务文件不要求额外中立段。
- A 为支撑 0/提醒关，B 为支撑 1/提醒关，C 为支撑 1/提醒开。
- 单 RFP-602 原始值仅作未标定代理量。

- Go/No-Go 采用 `GO / NO-GO / NOT-EVALUABLE` 三态。
- 舒适度首版工程线为 `>=5/7`。

总体判定：`有线双 IMU + RFP-602 原始采集链路及其格式适配通过；目标硬件腕角精度、RUD 修正、FSR 压力标定和人体 Go/No-Go 尚未建立。`

## 独立 CAL 边界

独立 CAL 和任务文件分别启动姿态滤波。该路径使用开始约 `0.5 s` 的有效加速度中值初始化倾角，初始航向固定为零；公开数据和原嵌入式校准路径仍保持单位四元数初始化，避免改变已有模型分布。

当前已验证的是软件可重复应用校准档案，不是目标硬件角度精度。六轴数据无法独立观测绕重力方向航向，因此必须满足：

- CAL 后 IMU 与护腕不移动。
- 两颗 IMU 轴向不变。
- CAL 和任务启动姿态可重复。
- 移动或重戴后重新 CAL 并更换 `calibration_id`。

## 合成 A/B/C 联调

数据状态固定为：

```text
SYNTHETIC DEMONSTRATION ONLY - NOT HUMAN EXPERIMENT RESULTS
```

当前生成器创建 8 名合成参与者，每个条件 `180 s`，前 `90 s` 键入、后 `90 s` 鼠标。结果：

| 比较 | `D_total` 平均降幅 | 解释 |
| --- | ---: | --- |
| A vs B | `27.66%` | 支撑增量 |
| B vs C | `53.98%` | 相同支撑下的提醒增量 |
| A vs C | `66.71%` | 支撑加提醒的组合影响 |

每名参与者的 A/B/C 均形成一个 `would_alert`；A/B 实际提醒为 0，C 实际提醒为 1。C 条件平均舒适度约为 `5.71/7`。所有条件的机械建议数均为 0。

合成输入只有未标定 RFP-602 ADC 代理量，没有 kPa 压力证据，因此：

```json
{
  "decision": "NOT-EVALUABLE",
  "failed_checks": [],
  "not_evaluable_checks": ["pressure_screening_pass"]
}
```

这些降幅由生成器主动构造，只验证代码路径，不能证明支撑或提醒对人体有效。
